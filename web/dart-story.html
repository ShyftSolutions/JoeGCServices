DART Tsunami Buoy Pipeline

From ocean floor pressure sensors to OGC-compliant API — how a single observation traverses 4 services in under a second.

🌏 The Source

DART (Deep-ocean Assessment and Reporting of Tsunamis) buoys are bottom pressure recorders deployed on the ocean floor at depths of 1,000–6,000m. Maintained by NOAA's PMEL, ~60 stations span the Pacific, Atlantic, Indian, and Caribbean basins.

📡 What They Measure

Each buoy measures water column height — the total pressure of the ocean above the sensor, converted to meters. During normal conditions, readings arrive every 15 minutes. When a seismic event is detected, the reporting frequency increases up to 900x.

T=1 Standard — 15 min
T=2 Event — 1 min
T=3 Triggered — 15 sec
📄 Raw Data Format

Each station's data is a space-delimited text file hosted at NDBC. The file contains ~45 days of history.

⚙ Pipeline Details

1
Discover Stations

The downloader fetches activestations.xml from NDBC and filters for stations with type="dart". This yields ~60 active buoys with their coordinates and names.

View station registry

2
Fetch Data

Each station's .dart file is fetched via HTTP GET, 10 stations concurrently using buffer_unordered(10). Each file is ~60–130 KB containing ~45 days of readings.

3
Parse & Transform

Raw text lines are split by whitespace. Date fields are combined into RFC 3339 timestamps. The measurement type (T=1/2/3) and height are extracted into structured IngestObservation objects.

4
POST to Ingester

Observations are batched (500 per request) and POSTed as JSON to the ingester's /ingest/observations endpoint with source: "dart".

5
Upsert Locations

The ingester creates/updates entries in the locations table using PostGIS ST_MakePoint(). A GIST spatial index enables fast geographic queries.

6
Store Observations

Observations are inserted into PostgreSQL with a unique constraint on (location_id, source, obs_time). Since the full 45-day history is re-fetched every 15 minutes, ON CONFLICT DO NOTHING deduplicates automatically.

7
Configure EDR

A YAML config registers the dart collection with data_type: pointobservation. This tells the EDR API to query PostgreSQL (not MinIO) and to filter by source='dart'. A 12-hour recency window controls which stations appear as "active".

8
Serve via EDR

The EDR API exposes 4 OGC-compliant query types: locations, locations/{id}, radius, and area. Responses are GeoJSON with water_column_height_m as the primary parameter.
